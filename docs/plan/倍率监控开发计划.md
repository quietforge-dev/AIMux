# 倍率监控开发计划

> 本文是待评审的实现方案，尚未修改数据库或功能代码。这里的“倍率监控”独立于现有的“监控管理”（账号可用性检测）；不复用、不修改 `monitor_records`、现有监控设置及旧表结构。

## 1. 目标与使用流程

新增侧边栏菜单“倍率监控”。用户创建一条监控配置，填写查询 URL、该接口的访问 token，选择若干 AIMux 账号并启用。后台每小时从该 URL 拉取所有 `status=active` 的 key 及其 `group.rate_multiplier`，按照账号 API key **精确匹配**，只在合法倍率与本地值不同的情况下更新该账号的 `accounts.multiplier`。页面展示配置的最近运行状态和按账号记录的监控日志。

同一家供应商的多个不同倍率账号可放进同一条配置；允许多条配置监控不同的 URL。查询失败、返回内容不完整、密钥未匹配或倍率无效时，不改相应账号。倍率监控**不调整**账号优先级、状态、平均耗时，也不触发现有账号可用性测试。

## 2. 现有代码现状与实现范围

- 现有账号在 `accounts` 表中有 `id`、`api_key_encrypted`、`multiplier` 等字段；字段虽名为 `api_key_encrypted`，当前代码实际保存和使用的是原始密钥，不能据字段名假设已加密。现有前后端账号倍率规则为 `0.01..=0.99`，页面显示两位小数。
- 普通 `/api/accounts` 列表被 controller 限制为最多 200 条。选择器应新建**只返回所需字段**的全量账号选项接口/DAO 查询，不调用分页接口后只拿第一页，也不把 API key 下发给选择器。
- Tauri 桌面版和 `aimux-gateway` 均可启动后台任务，且共用用户数据目录中的 `aimux.db`。新任务需独立于当前每两分钟执行的 `background/monitor_task.rs`，并处理两进程同时运行。
- 通过新增 `0007_*.sql` SQLx migration 建立**恰好两张新业务表**，保留已发布的 `0001`～`0006`，不在启动时手动 `ALTER TABLE`。账号倍率更新只是对已有字段做常规业务写入，不改变旧表定义。

## 3. 两张新表（拟定）

### `multiplier_monitor_configs`：监控配置

| 字段 | 用途 |
| --- | --- |
| `id` TEXT PRIMARY KEY | 配置 ID（UUID） |
| `name` TEXT NOT NULL | 用户可识别的配置名称 |
| `url` TEXT NOT NULL | 完整接口 URL；查询参数由程序构造 |
| `token` TEXT NOT NULL | 查询接口的 token，保存原值，不含自动添加的 `Bearer ` 前缀 |
| `account_ids` TEXT NOT NULL | 选中账号 ID 的 JSON 数组；只有两张新表，不另建关联表 |
| `enabled` INTEGER NOT NULL | 是否启用，默认 1 |
| `last_started_at`, `last_finished_at` TEXT | 调度间隔及页面状态；新配置为空即尽快检查 |
| `lease_owner`, `lease_until` TEXT | 跨进程防重复执行的租约；过期后可接管 |
| `created_at`, `updated_at` TEXT NOT NULL | 创建、编辑及并发变更检测 |

对 `enabled`、到期时间建立索引。配置创建/编辑时校验名称、URL、token、账号 ID 列表：至少一个账号、去重、每个 ID 都存在；可选禁止同一账号同时出现在多条**启用**配置中，以免不同来源相互覆盖。本方案建议禁止冲突，并在保存和执行时校验。编辑时 URL/token/账号集合改变，清空上次检查时间，使新配置尽快生效；仅改名称不重置周期。删除配置前先明确日志保留语义：建议软禁用而非物理删除；若提供物理删除，需在 UI 二次确认并说明相关日志是否保留。

`account_ids` 使用 JSON 是“两张表”限制下的折中：无法用外键约束数组成员。删除账号后历史配置里可以保留无效 ID，页面显示“账号已删除”，运行时跳过并写日志；编辑配置时要求用户清理。配置读写要解析并验证 JSON，不依赖 `LIKE` 查询账号 ID。

### `multiplier_monitor_logs`：监控日志

每次运行生成一个 `run_id`，每个选中账号写一条结果；整个 HTTP/分页/解析流程失败时额外写一条 `account_id = NULL` 的配置级错误。拟定字段：`id`、`run_id`、`config_id`、`config_name`（名称快照）、`account_id`（可空）、`account_name`（快照）、`started_at`、`finished_at`、`duration_ms`、`result`（`updated` / `unchanged` / `missing_key` / `invalid_rate` / `account_missing` / `conflict` / `failed`）、`old_multiplier`、`remote_multiplier`、`error_code`、`error_message`、`http_status`。以 `config_id, started_at DESC, id DESC` 和 `run_id` 建索引，日志页按 SQL 分页。

日志**绝不保存或回传** token、完整账号 key、Authorization 头、带凭据的 URL、原始响应体。错误消息先做脱敏和长度限制，避免上游把凭据反射到错误正文。账号或配置后来改名时，仍可用快照辨认旧日志。日志清理策略需确定（建议默认保留最近 90 天或限定单配置条数，仅清理新日志表）。

### 3.1 `0007_multiplier_monitor.sql` 完整建表语句

迁移文件只新增下面两张表和索引，不修改 `accounts`、`models`、`monitor_records` 或其他已发布表。遵循项目当前约定，除主键和必要的非空字段外，不给 `enabled`、`result`、倍率等业务值增加数据库 CHECK 约束，统一由前端提示和 Rust service 校验。`account_ids` 是 JSON 数组，不能建立账号外键；日志也不设置配置/账号外键，以便账号或配置删除后继续保留历史记录。

```sql
-- src-tauri/migrations/0007_multiplier_monitor.sql
```

`token` 当前按项目既有账号密钥的安全边界保存在用户本地 SQLite 中，但任何列表/详情 API 都不返回明文，编辑时空 token 表示保留旧值。`result` 不做枚举约束，后续新增 `cancelled`、`skipped_disabled` 等结果时无需重建日志表。配置删除时不级联日志；如果最终产品不提供物理删除，则只通过 `enabled=0` 停用。

## 4. 页面和 API

- 新增侧栏菜单、路由 `/multiplier-monitor`，独立页面，不改现有“监控管理”页面。
- 配置列表：名称、脱敏 URL、所选账号数量、启停、最近开始/完成时间、最近结果摘要、编辑、立即检查、查看日志；检查进行中显示加载状态并禁止重复触发，异常/部分匹配/全部成功有清楚的反馈。
- 配置弹窗：名称、URL、token（密码输入；编辑时后端不回传明文，留空表示保留原值）、左右账号选择器。左侧从专用全量选项接口取当前所有账号，可搜索名称/类型/状态/当前倍率；右侧是已选账号并可移除，选中后立即从左侧消失。保留右侧原有顺序；已删除账号标记并提示处理。账号多时仍一次拉取，但后端设置合理数量上限和响应大小保护。
- 日志弹窗/页面：按配置、时间、结果筛选，显示账号、旧倍率→新倍率/远端倍率、更新时间、失败原因；没有匹配 key 的情况明确写为“未匹配，未更新”。
- 拟定 API：`GET/POST /api/multiplier-monitors`，`PUT /api/multiplier-monitors/{id}`，`POST /api/multiplier-monitors/{id}/toggle`，`POST /api/multiplier-monitors/{id}/check`，`GET /api/multiplier-monitors/{id}/logs?offset=&limit=`，`GET /api/multiplier-monitors/account-options`。如需删除，单独增加 DELETE 并先确定日志策略。所有请求经现有 `src/api/client.ts` 和 Axum 管理接口鉴权。
- 配置 DTO 不返回 token；创建必须填写，编辑留空表示不修改。响应可返回 `has_token: true`。服务端拒绝设置到 URL 的用户名/密码或包含 token 的 URL 查询参数（避免泄露），并在页面提示填写在 token 栏。

## 5. Rust 查询与匹配规则

1. 独立 service 使用当前设置的代理配置，创建带超时的 Reqwest 客户端；GET 使用 URL 的原有非敏感查询参数并**覆盖** `page`、`page_size=100`、`status=active`、`timezone=Asia/Shanghai`，防止重复参数。token 若已有不区分大小写的 `Bearer ` 前缀则不再添加，否则发送 `Authorization: Bearer <token>`；发送 `Accept: application/json`。拒绝 URL 内凭据、非 HTTP(S) 协议；默认只允许 HTTPS，若确需内网 HTTP 要由 UI 明确提示风险。禁止跨域重定向携带 Authorization（建议该客户端禁用重定向）。
2. 从第 1 页顺序抓取所有页，而非只处理 Java 示例的第一页。每页要求 HTTP 2xx、顶层 `code` 表示业务成功（具体成功码须以真实响应确认，计划暂定 `0`）、`data.items` 为数组，并核对 `page`、`page_size`、`pages`、`total` 的一致性。设置最大页数、最大响应体、最大总条数、单页/整体超时，避免不可信服务拖死任务。只有**全部分页完成且验证通过**，才考虑更新数据库；某页失败、分页变化/截断或重复 key 且倍率冲突时，该配置本轮全部不更新，写一条配置级失败日志。
3. 对每条 item 只读取完整 `key` 和 `group.rate_multiplier`；不能用部分匹配、前后四位或脱敏 key 做关联。完整 key 只在内存使用，不进入日志和 API。匹配前仅去除意外首尾空白；不要删除中间字符、大小写折叠或从账号 key 任意剥离 `Bearer `，以免错误匹配。相同 key 的多个已选账号可各自更新；远端重复 key 需确认值相同，否则整轮失败。
4. 先建立本轮 `key -> 倍率` 映射，再用配置中的账号 ID 重新读取账号最新密钥/倍率/状态。停用账号默认仍可选但**不自动更新**，记为跳过；若需求是停用也要同步，评审时改此规则。账号不存在、密钥缺失或未命中，记录跳过，不更新。未匹配的账号不能因为成功抓到其他 key 而清空或改倍率。
5. 对倍率按十进制解析（推荐 `rust_decimal`；接受 JSON 数值或明确的数字字符串），拒绝 `null`、非数、负值、非有限值、超出 `0.01..=0.99` 或超过两位有效小数的值；`0.300` 与 `0.30` 视为相同。不得用浮点精度噪声触发反复写入或悄悄四舍五入。比较相等则记 `unchanged`；不等才更新现有 `accounts.multiplier`、`updated_at`，不调用会改优先级/错误状态的账号调整方法。
6. 对有效数据的账号写入采用**带旧密钥/旧倍率条件的事务内更新**，编辑账号或更换密钥后若条件不符则 `conflict`、不覆盖；更新和该条 `updated` 日志在同一事务中提交。若配置在网络请求期间被编辑、停用或删除，本轮写入前检测配置版本 `updated_at`，整轮停止并记录取消，不继续用旧配置更新账号。单账号 DB 错误回滚本轮写入，记录配置级失败；不产生部分成功却声称整体成功的状态。

### 5.1 Rust 查询工具方法

Rust 没有 Java 风格的静态工具类，建议实现为独立模块 `src-tauri/src/service/multiplier_query.rs`。它只做 URL 校验、Authorization 处理、HTTP GET、分页和 `key`/`rate_multiplier` 提取，不读取或更新数据库。这样后台定时检查和页面“立即检查”可以复用同一个方法，账号匹配与写入仍由 `multiplier_monitor_service.rs` 负责。

下面代码是在 Java `getJson` 基础上的 Rust 版本，并补上生产环境需要的完整分页、响应大小限制、代理、超时和敏感信息保护：

```rust
use std::time::Duration;

use futures_util::StreamExt;
use reqwest::{
    header::{ACCEPT, AUTHORIZATION},
    redirect::Policy,
    Client, Response, Url,
};
use serde::Deserialize;
use serde_json::Value;

use crate::{
    config::Settings,
    error::AppError,
    upstream::proxy,
};

const PAGE_SIZE: usize = 100;
const SUCCESS_CODE: i64 = 0; // 实施前根据真实接口响应确认
const QUERY_TIMEOUT: Duration = Duration::from_secs(40);
const MAX_PAGE_RESPONSE_BYTES: usize = 4 * 1024 * 1024;
const MAX_PAGES: usize = 10_000;
const MAX_ITEMS: usize = 1_000_000;

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct RemoteMultiplier {
    pub key: String,
    /// 保留远端十进制文本，后续由 service 使用 Decimal 精确校验和比较。
    pub rate_multiplier: Option<String>,
    pub rate_error: Option<String>,
}

#[derive(Debug, Deserialize)]
struct RootResponse {
    code: i64,
    #[serde(default, rename = "message")]
    _message: Option<String>,
    data: PageData,
}

#[derive(Debug, Deserialize)]
struct PageData {
    items: Vec<RemoteItem>,
    total: usize,
    page: usize,
    page_size: usize,
    pages: usize,
}

#[derive(Debug, Deserialize)]
struct RemoteItem {
    key: Option<String>,
    group: Option<RemoteGroup>,
}

#[derive(Debug, Deserialize)]
struct RemoteGroup {
    rate_multiplier: Option<Value>,
}

/// 对应 Java getJson：GET 查询并返回所有分页中的 key 与倍率。
pub async fn fetch_all(
    raw_url: &str,
    raw_token: &str,
    settings: &Settings,
) -> Result<Vec<RemoteMultiplier>, AppError> {
    let base_url = validated_url(raw_url)?;
    let authorization = authorization_value(raw_token)?;
    let http = build_client(settings)?;

    let mut result = Vec::new();
    let mut received_items = 0usize;
    let mut page = 1usize;
    let mut expected_total: Option<usize> = None;
    let mut expected_pages: Option<usize> = None;

    loop {
        if page > MAX_PAGES {
            return Err(AppError::Upstream("倍率查询分页超过安全上限".into()));
        }

        let page_url = with_page_query(&base_url, page);
        let response = http
            .get(page_url)
            .header(AUTHORIZATION, &authorization)
            .header(ACCEPT, "application/json")
            .send()
            .await
            .map_err(|error| AppError::Upstream(format!("倍率查询请求失败: {error}")))?;
        let status = response.status();
        if !status.is_success() {
            // 不记录原始 body，避免第三方接口在响应中反射 token/key。
            return Err(AppError::Upstream(format!(
                "倍率查询接口返回 HTTP {}",
                status.as_u16()
            )));
        }

        let bytes = read_limited(response, MAX_PAGE_RESPONSE_BYTES).await?;
        let root: RootResponse = serde_json::from_slice(&bytes)
            .map_err(|_| AppError::Upstream("倍率查询接口返回的不是有效 JSON".into()))?;
        if root.code != SUCCESS_CODE {
            return Err(AppError::Upstream(format!(
                "倍率查询业务失败，code={}",
                root.code
            )));
        }

        let data = root.data;
        let effective_pages = data.pages.max(1); // 兼容空结果返回 pages=0
        if data.page != page || data.page_size != PAGE_SIZE {
            return Err(AppError::Upstream("倍率查询分页信息不一致".into()));
        }
        match (expected_total, expected_pages) {
            (None, None) => {
                if data.total > MAX_ITEMS || effective_pages > MAX_PAGES {
                    return Err(AppError::Upstream("倍率查询数据量超过安全上限".into()));
                }
                expected_total = Some(data.total);
                expected_pages = Some(effective_pages);
            }
            (Some(total), Some(pages))
                if total != data.total || pages != effective_pages =>
            {
                return Err(AppError::Upstream(
                    "倍率查询期间 total/pages 发生变化".into(),
                ));
            }
            _ => {}
        }

        received_items = received_items
            .checked_add(data.items.len())
            .ok_or_else(|| AppError::Upstream("倍率查询条数溢出".into()))?;
        if received_items > MAX_ITEMS {
            return Err(AppError::Upstream("倍率查询条数超过安全上限".into()));
        }
        for item in data.items {
            // 与 Java 一样跳过没有 item/key 的记录，但最终仍用原始 items 数核对 total。
            let Some(key) = item.key.map(|value| value.trim().to_owned()) else {
                continue;
            };
            if key.is_empty() {
                continue;
            }
            let (rate_multiplier, rate_error) = extract_rate(
                item.group.and_then(|group| group.rate_multiplier),
            );
            result.push(RemoteMultiplier {
                key,
                rate_multiplier,
                rate_error,
            });
        }

        if page >= expected_pages.unwrap_or(1) {
            if Some(received_items) != expected_total {
                return Err(AppError::Upstream(
                    "倍率查询实际条数与 total 不一致".into(),
                ));
            }
            break;
        }
        page += 1;
    }

    Ok(result)
}

fn validated_url(raw_url: &str) -> Result<Url, AppError> {
    let url = Url::parse(raw_url.trim())
        .map_err(|error| AppError::BadRequest(format!("倍率查询 URL 无效: {error}")))?;
    if !matches!(url.scheme(), "http" | "https") || url.host_str().is_none() {
        return Err(AppError::BadRequest(
            "倍率查询 URL 必须使用 http 或 https 且包含主机".into(),
        ));
    }
    if !url.username().is_empty() || url.password().is_some() {
        return Err(AppError::BadRequest(
            "倍率查询 URL 不能包含用户名或密码".into(),
        ));
    }
    Ok(url)
}

fn authorization_value(raw_token: &str) -> Result<String, AppError> {
    let token = raw_token.trim();
    if token.is_empty() {
        return Err(AppError::BadRequest("倍率查询 token 不能为空".into()));
    }
    let has_bearer = token
        .get(..7)
        .map(|prefix| prefix.eq_ignore_ascii_case("Bearer "))
        .unwrap_or(false);
    Ok(if has_bearer {
        token.to_owned()
    } else {
        format!("Bearer {token}")
    })
}

fn build_client(settings: &Settings) -> Result<Client, AppError> {
    // 禁止自动重定向，避免 Authorization 被带到另一个主机。
    let mut builder = Client::builder()
        .timeout(QUERY_TIMEOUT)
        .redirect(Policy::none());
    if let Some(configured_proxy) =
        proxy::proxy(settings).map_err(|error| AppError::Internal(error.to_string()))?
    {
        builder = builder.proxy(configured_proxy);
    }
    builder
        .build()
        .map_err(|error| AppError::Internal(error.to_string()))
}

fn with_page_query(base_url: &Url, page: usize) -> Url {
    let fixed = ["page", "page_size", "status", "timezone"];
    let original = base_url
        .query_pairs()
        .filter(|(name, _)| !fixed.iter().any(|fixed_name| name == *fixed_name))
        .map(|(name, value)| (name.into_owned(), value.into_owned()))
        .collect::<Vec<_>>();
    let mut url = base_url.clone();
    url.set_query(None);
    {
        let mut query = url.query_pairs_mut();
        for (name, value) in original {
            query.append_pair(&name, &value);
        }
        query
            .append_pair("page", &page.to_string())
            .append_pair("page_size", &PAGE_SIZE.to_string())
            .append_pair("status", "active")
            .append_pair("timezone", "Asia/Shanghai");
    }
    url
}

async fn read_limited(response: Response, limit: usize) -> Result<Vec<u8>, AppError> {
    if response
        .content_length()
        .map(|length| length > limit as u64)
        .unwrap_or(false)
    {
        return Err(AppError::Upstream("倍率查询响应超过大小限制".into()));
    }
    let mut bytes = Vec::new();
    let mut stream = response.bytes_stream();
    while let Some(chunk) = stream.next().await {
        let chunk = chunk
            .map_err(|error| AppError::Upstream(format!("读取倍率查询响应失败: {error}")))?;
        if bytes.len() + chunk.len() > limit {
            return Err(AppError::Upstream("倍率查询响应超过大小限制".into()));
        }
        bytes.extend_from_slice(&chunk);
    }
    Ok(bytes)
}

fn extract_rate(value: Option<Value>) -> (Option<String>, Option<String>) {
    let Some(value) = value else {
        return (None, None);
    };
    let text = match value {
        Value::Number(number) => number.to_string(),
        Value::String(text) => text.trim().to_owned(),
        _ => return (None, Some("rate_multiplier 不是数字".into())),
    };
    if text.is_empty() {
        (None, Some("rate_multiplier 为空".into()))
    } else {
        (Some(text), None)
    }
}
```

该工具保留倍率的十进制字符串，不在查询层转成 `f64`，避免 `0.1` 一类值产生二进制浮点误差。正式实现时在 service 层增加 `rust_decimal` 依赖，将字符串解析为 `Decimal`，再校验 `0.01..=0.99`、小数位和新旧值是否相同。远端出现重复 key 时：倍率相同可合并，倍率不同必须将本轮判为失败并保持所有账号不变。

## 6. 每小时调度与多实例

- 单独的后台任务每分钟扫一次启用配置，`last_started_at` 为空或距今至少 1 小时时才到期；首次创建配置可尽快执行。手动“立即检查”不必等一小时，但同一配置在运行时返回“正在检查”，不重入；手动执行也更新下次自动执行的起算时间。
- 桌面版 `run()` 和独立网关 `run_gateway()` 都要挂载任务。两者可能共用同一数据库，所以必须通过**原子 SQL 条件更新**取得配置租约（检查 `lease_until` 已过期），不是仅靠进程内 mutex。完成或失败后释放租约，异常退出可在租约到期后恢复；租约时长需覆盖整个任务硬超时，避免尚在执行时被另一进程接管。
- 每次循环重新查询配置，不缓存旧账号密钥；每个配置串行抓页，不同配置并发数有上限（建议 2）。使用 `MissedTickBehavior::Skip` 避免长时间请求造成补跑风暴；下一次根据数据库的 `last_started_at` 算，不靠进程启动时间。关闭配置立即阻止新的运行，已在途轮次在写入前再次确认启用及版本。
- 请求错误、超时、解析失败均写日志并更新最后完成时间，但绝不改账号倍率；不要因单个配置失败阻塞其他配置。只记录脱敏摘要到 tracing。必要时做日志保留清理，不能触碰现有 `monitor_records`。

## 8. 验收场景

- 新老数据库启动成功，只多出两张业务表；旧账号及旧监控记录不变。
- 配置选多账号，左右待选/已选互斥；账号数超过 200 时仍可完整选择；编辑后不泄露 token 或账号 key。
- 首页 `page_size=100` 恰好 100 条、下一页才有目标 key 时能命中；任何一页失败/总数不一致时**整轮零更新**。
- 远端与本地相同不写；不同且合法才更新；一个配置包含同 key 的多个账号时都能更新；缺失 key、账号已删/已停用、非法倍率、重复冲突 key 均不误写。
- 页面手动检查与后台自动检查碰撞、双进程共库、配置在请求中被编辑/禁用、账号在请求中改 key/倍率时，不重复更新或覆盖新值；租约过期后可恢复。
- HTTP 401/403、5xx、超时、响应不是 JSON、业务 `code` 失败、缺 `data.items` 和空列表均写明确且脱敏的结果；不要把空列表当作“所有倍率变 0”。
