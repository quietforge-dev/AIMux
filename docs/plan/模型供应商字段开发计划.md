# 模型供应商字段开发计划

> 状态：待开发  
> 更新日期：2026-09-18  
> 本文是后续开发依据，当前版本尚未实现模型供应商字段。

## 1. 需求目标

在“模型维护”中为模型增加独立的供应商字段 `provider`，用于标识模型所属厂商或品牌方。

当前模型只有：

- `name`：请求时使用的模型名称。
- `type`：请求协议，目前为 `openai` 或 `anthropic`。
- `is_default`：是否为该协议的测试默认模型。

新增后模型字段含义为：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `name` | 请求时使用的模型名称 | `deepseek-chat` |
| `type` | 请求协议 | `openai` |
| `provider` | 模型供应商 | `deepseek` |
| `is_default` | 是否为该协议的测试默认模型 | `0` |

`type` 和 `provider` 是两个不同概念：

- `type` 决定模型使用 OpenAI 兼容协议还是 Anthropic 协议。
- `provider` 只表示模型归属，用于模型维护中的保存、展示和筛选。
- Grok、Kimi、DeepSeek、Qwen 等模型可以使用 OpenAI 兼容协议，但供应商不是 OpenAI。

## 2. 实现范围

本次只实现模型供应商元数据：

1. 只给 `models` 表增加 `provider`。
2. 根据现有模型的 `type` 回填历史数据。
3. 模型维护列表增加供应商列和供应商筛选。
4. 模型新增、编辑表单增加供应商字段。
5. 模型 API、Rust model/schema/DAO/service 支持读写和筛选 `provider`。
6. 默认模型继续按 `type` 管理，不改为按供应商分组。

明确不在本次范围内：

- 不修改 `accounts` 表和账号接口。
- 不在账号管理中增加供应商。
- 不修改账号的支持模型和测试模型逻辑。
- 不修改网关选号、调度、重试和模型映射逻辑。
- 不修改后台监控、监控记录和监控页面。
- 不修改使用记录、统计和兼容模型列表接口的行为。
- 不修改账号 JSON 导入导出格式。

实现时不得因为模型增加了 `provider`，继续扩展账号、调度或监控功能。

## 3. 供应商选项

前端预置常见供应商，数据库保存稳定的英文代码，页面显示对应品牌名称。

| 保存值 | 页面显示 | 常见模型或品牌 |
| --- | --- | --- |
| `openai` | OpenAI | GPT、o 系列 |
| `anthropic` | Anthropic | Claude |
| `xai` | xAI | Grok |
| `google` | Google | Gemini、Gemma |
| `deepseek` | DeepSeek | DeepSeek |
| `moonshot` | Moonshot AI | Kimi |
| `alibaba` | Alibaba Cloud | Qwen、通义千问 |
| `zhipu` | 智谱 AI | GLM |

供应商代码与模型品牌的对应关系：

- Grok 保存为 `xai`。
- Kimi 保存为 `moonshot`。
- Qwen 保存为 `alibaba`。
- Claude 保存为 `anthropic`。
- Gemini 保存为 `google`。

本次前端只提供表格中列出的 8 个供应商，不允许在界面输入自定义供应商。数据库不增加供应商枚举 CHECK 约束，允许值由前端选项和 TypeScript 类型控制。

## 4. 数据库迁移

### 4.1 Migration 文件

新增：

```text
src-tauri/migrations/0006_models_provider.sql
```

不得修改已经发布的：

- `0001_baseline.sql`
- `0003_models_one_default.sql`

### 4.2 字段定义

`models` 表增加：

```sql
provider TEXT NOT NULL
```

不增加 `ck_models_provider` 或其他供应商枚举约束。

由于 `provider` 必须为真正的非空字段，推荐通过临时表重建 `models`，而不是长期保留列默认值。

### 4.3 历史数据回填

现有模型按照 `type` 回填：

```sql
CASE
    WHEN type = 'anthropic' THEN 'anthropic'
    WHEN type = 'openai' THEN 'openai'
END
```

迁移不根据模型名称猜测 Grok、Kimi、DeepSeek 或 Qwen。升级后，用户可以在模型维护中手动修改供应商。

### 4.4 重建要求

迁移需要完整保留：

- `id`
- `name`
- `type`
- `is_default`
- `created_at`
- `updated_at`

模型唯一规则保持不变：

```text
UNIQUE(type, name)
```

默认模型规则保持不变：每个 `type` 最多一个 `is_default = 1`。

重建表后恢复现有索引和约束：

- `ck_models_type`
- `uq_models_type_name`
- `idx_models_type_name`
- `ix_models_name`
- `ix_models_type`
- `uq_models_one_default_per_type`

新增供应商筛选索引：

```sql
CREATE INDEX ix_models_provider_type ON models(provider, type);
```

现有 `ix_models_type` 继续服务仅按协议筛选；`ix_models_provider_type` 服务仅按供应商或按供应商和协议组合筛选。不再额外创建功能重叠的 `ix_models_provider`、`ix_models_type_provider`。

## 5. 后端开发细节

### 5.1 Rust 数据结构

以下类型增加 `provider`：

- `CatalogModel`：`provider: String`
- `ModelCreate`：`provider: String`
- `ModelUpdate`：`provider: Option<String>`
- `ModelView`：`provider: String`

模型接口返回示例：

```json
{
  "id": "model-id",
  "name": "deepseek-chat",
  "type": "openai",
  "provider": "deepseek",
  "is_default": 0,
  "created_at": "2026-09-18T00:00:00Z",
  "updated_at": "2026-09-18T00:00:00Z"
}
```

### 5.2 DAO

`model_dao` 需要同步修改：

- 创建模型时写入 `provider`。
- 编辑模型时更新 `provider`。
- `to_view` 返回 `provider`。
- `insert_missing` 的默认模型参数改成 `(type, provider, name)`。
- 列表支持同时按 `type` 和 `provider` 筛选。
- 列表排序为 `type, is_default DESC, provider, lower(name), id`，保持每种协议的默认模型优先展示。

模型名称唯一校验继续使用 `(type, name)`，供应商不参与唯一判断。

### 5.3 校验

创建和更新模型共用同一套校验：

- `name.trim()` 不能为空。
- `type` 只能是 `openai` 或 `anthropic`。
- `provider.trim()` 不能为空。
- 后端和数据库不校验供应商是否属于前端预置列表。

更新模型时，即使请求修改的只是供应商，也必须校验合并后的完整模型数据，不能只校验请求中出现的字段。

### 5.4 默认模型

默认模型逻辑保持现状：

- `set_default` 仍然清除同一 `type` 下的旧默认模型。
- `ensure_defaults` 仍然按 `openai`、`anthropic` 两种 `type` 补齐默认模型。
- 修改 `provider` 不清除 `is_default`。
- 删除模型后的默认模型补齐规则不变。
- `uq_models_one_default_per_type` 保持不变。

### 5.5 默认模型初始化

`model_service::DEFAULTS` 增加供应商信息：

```rust
const DEFAULTS: [(&str, &str, &str); 7] = [
    ("openai", "openai", "gpt-5.6-sol"),
    ("openai", "openai", "gpt-5.6-terra"),
    ("openai", "openai", "gpt-5.6-luna"),
    ("openai", "openai", "gpt-6-astra"),
    ("anthropic", "anthropic", "claude-opus-5"),
    ("anthropic", "anthropic", "claude-sonnet-5"),
    ("anthropic", "anthropic", "claude-fable-5-1"),
];
```

参数顺序固定为：

```text
(type, provider, name)
```

Migration 负责升级已有数据；`DEFAULTS` 只负责新安装和启动时补齐缺失的内置模型。

### 5.6 列表接口筛选

模型列表接口支持：

```http
GET /api/models?type=openai&provider=deepseek
```

两个条件都是可选的，同时提交时使用“且”关系。

需要同步修改：

- `model_controller` 查询参数。
- `model_service::list` 参数。
- `model_dao::list` 参数和 SQL 绑定。

不得根据 `provider` 改变网关兼容接口和请求协议。

## 6. 前端开发细节

### 6.1 API 类型

`CatalogModel` 增加：

```ts
provider:
  | 'openai'
  | 'anthropic'
  | 'xai'
  | 'google'
  | 'deepseek'
  | 'moonshot'
  | 'alibaba'
  | 'zhipu';
```

`modelsApi.list` 使用 `URLSearchParams` 构造可选的 `type` 和 `provider` 查询参数，不手工拼接多个条件。

供应商显示名称和 Logo 路径集中维护在一个前端常量映射中，列表、筛选和表单共用，不在多个组件内重复声明。

### 6.2 模型维护列表

推荐列顺序：

1. 模型名称
2. 供应商
3. 协议类型
4. 测试默认
5. 操作

页面工具栏保留协议类型筛选，并增加供应商筛选。两个筛选条件同时选择时使用“且”关系。

供应商显示规则：

- 预置供应商显示对应品牌名称。
- 不根据模型名称自动推断供应商。
- 供应商名称前显示对应本地 Logo。

### 6.3 新增和编辑表单

表单字段顺序：

1. 模型名称
2. 协议类型
3. 供应商

供应商字段要求：

- 必填。
- 可搜索。
- 展示预置选项。
- 不允许创建自定义值。
- 每个选项的名称前显示对应本地 Logo。
- 新增模型时，默认根据协议带出：`openai -> openai`、`anthropic -> anthropic`。
- 用户已经手动选择供应商后，切换协议时不自动覆盖。
- 编辑模型时直接回显数据库中的供应商。

页面中的“类型”文案建议改为“协议类型”，避免与供应商混淆。

表单不要继续使用 `reactive<any>`，应定义明确的模型表单类型，至少包含：

```ts
type ModelForm = {
  id?: string;
  name: string;
  type: CatalogModel['type'];
  provider: CatalogModel['provider'];
};
```

## 7. 兼容性

- 前端和后端在同一应用版本中一起发布。
- 旧数据库通过 `0006_models_provider.sql` 自动回填供应商。
- 新数据库从 `0001` 执行到最新 migration 后，`models.provider` 必须存在且非空。
- 现有模型 ID、名称、协议、默认状态和时间字段保持不变。
- 账号、调度、监控和使用记录行为保持不变。
- 模型的 `provider` 目前只作为管理元数据，不参与任何请求路径或账号选择。

## 8. 测试计划

### 8.1 数据库迁移

- 旧数据库升级后模型数量不变。
- 所有原有模型字段和默认状态保持不变。
- `type = 'openai'` 回填 `provider = 'openai'`。
- `type = 'anthropic'` 回填 `provider = 'anthropic'`。
- `provider` 为 `NOT NULL`。
- `(type, name)` 唯一约束仍然有效。
- 每个 `type` 最多一个默认模型的约束仍然有效。
- 原有模型索引和新增供应商筛选索引存在。
- 从 `0001` 到最新 migration 的全新数据库可以正常启动。

### 8.2 后端

- 创建模型可以保存预置供应商。
- 编辑模型可以只修改供应商。
- 空供应商被拒绝，数据库不存在供应商枚举 CHECK 约束。
- 更新接口不能写入非法 `type`。
- 同一 `type` 下重复模型名仍然被拒绝。
- 修改供应商不影响当前默认模型状态。
- 默认模型 seed 写入正确供应商。
- 列表可以按协议、供应商以及两者组合筛选。

### 8.3 前端与回归

- 列表、筛选和表单选项都正确显示供应商名称与 Logo。
- 协议和供应商筛选可以单独或组合使用。
- 新增、编辑表单正确保存和回显供应商。
- 表单供应商默认值和手动修改行为符合设计。
- 账号管理、监控、使用记录和统计页面行为不变。
- OpenAI 和 Anthropic 请求协议行为不变。

## 9. 验收标准

1. 模型维护可以查看、筛选、新增和编辑供应商。
2. 升级用户的所有历史模型都获得非空供应商，且没有数据丢失。
3. `type` 明确表示协议，`provider` 明确表示模型供应商。
4. Grok、Kimi、DeepSeek、Qwen 等模型可以设置正确供应商，同时保留原协议类型。
5. 默认模型仍按协议类型管理，不受供应商影响。
6. 账号、调度、监控和使用记录没有行为变化。
7. Migration、Rust 测试和前端构建全部通过。
