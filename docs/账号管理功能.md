# 账号管理功能

## 1. 列表和排序

账号管理页启动或点击“刷新”时调用 `GET /api/accounts?limit=200&status=active`，顶部状态 Tab 提供全部、启用和禁用筛选，默认显示启用账号；切换 Tab 后会按状态重新查询。列表排序固定为：

1. `active` 启用账号优先于 `disabled` 停用账号。
2. 同状态按优先级降序，9 最先被看到和调度。
3. 同优先级按名称不区分大小写升序。
4. 名称相同按账号 ID 升序作为稳定兜底。

表格包含选择、名称、类型、状态、倍率、优先级、优先级快捷操作、最近使用和操作列。名称和优先级可以直接编辑；账号数据变化后页面会重新读取最新列表。

## 2. 新增、编辑和复制

新增/编辑表单字段为名称、类型、上游地址、API 密钥、优先级、倍率、支持模型、测试默认模型、模型映射、标签和备注。其中名称、类型、上游地址、API 密钥、优先级、倍率、支持模型和测试默认模型为必填项，标签前以红色 `*` 标识；保存时在当前表单内校验，缺失字段会提示且不会关闭弹窗。优先级范围为 0 至 9；倍率范围为 `0.01` 至 `0.30`，默认 `0.10`。API 密钥以明文回显并可编辑。上游地址会去除末尾 `/`。

支持模型从模型维护目录加载，并随协议类型切换过滤，至少选择一个。编辑时即使某个已保存模型已从目录删除，它仍会在表单中保留，避免无意丢失配置。复制会预填包括倍率和 API 密钥在内的账号字段，并作为新增账号提交。操作列的“JSON”按钮会将账号配置复制为 `aimux-account` 格式的 JSON；JSON 包含名称、协议、上游地址、API 密钥、优先级、倍率、支持模型、测试默认模型、模型映射、标签和备注，不包含账号 ID、状态、请求统计、监控结果和时间字段。新增账号区域的“从 JSON 导入”会在校验后回填新增表单，用户仍需确认并点击保存；编辑账号时不提供该入口，导入后默认启用。导入时即使支持模型或映射目标不在当前电脑的模型目录中，也会保留到表单中。

测试默认模型位于支持模型之后，只能从当前已勾选的支持模型中选择；取消勾选当前测试模型会自动清空该配置并回退到模型维护默认值。它用于账号测试和后台监控。模型选择顺序为：手动测试时明确选择的模型 → 账号测试默认模型 → 模型维护中该协议的默认模型。批量测试选择“使用账号默认模型”时，每个账号按自己的配置分别解析。

模型映射是账号级的精确映射，格式为“客户端模型 -> 上游模型”，例如 `gpt-5.5 -> grok4.6`。客户端模型下拉框只显示当前已勾选的支持模型，上游模型下拉框显示当前协议类型的全部模型目录；编辑历史账号时不在目录中的已有值仍会保留并可重新选择。客户端模型用于调度选号，选中账号后才应用该账号映射；未配置或未命中时保持原模型。真实请求、账号测试和后台监控都会使用映射后的上游模型；每次重试都会按当前账号重新解析。映射行允许为空配置，但已添加的行必须选择两端且客户端模型不能重复。

API 密钥在本地数据库中明文保存，`AccountView` 返回密钥供编辑表单回显。

JSON 导出内容包含明文 API 密钥，仅写入系统剪切板，不在服务端保存或日志中记录；跨电脑传输时应使用可信渠道，使用后及时清理剪切板。

## 3. 状态和优先级

状态列是可直接点击的“启用/禁用”按钮。禁用账号不会被调度器选中，但测试成功或失败不会改变这个人工状态。

真实请求成功时优先级 `+1`，失败时 `-1`；连接测试成功时 `+3`，失败时 `-1`。所有调整都限制在 0 至 9。快捷操作列提供 0、3、6、9 四个圆形按钮，点击后直接将账号优先级设置为对应数值，与优先级编辑框使用同一保存逻辑。

## 4. 测试

单账号测试点击“测试”后打开测试弹窗，从该账号保存的支持模型中选择客户端模型，并发送最小请求（`max_tokens=1`、用户内容为 `ping`）。对于未保存支持模型的历史账号，才回退显示当前协议的模型目录。OpenAI 使用 `/v1/chat/completions`，Anthropic 使用 `/v1/messages`。

批量测试需要先勾选账号，且所有选中账号必须是同一种协议类型；混合类型会提示拆分操作。统一弹窗会在后台线程中逐个调用单账号测试接口，实时展示当前账号、进度和结果；一个账号失败或网络异常不会中断后续账号。

## 5. 管理 API

| 操作 | 接口 |
|---|---|
| 列表 | `GET /api/accounts` |
| 新增 | `POST /api/accounts` |
| 详情 | `GET /api/accounts/{account_id}` |
| 编辑 | `PUT /api/accounts/{account_id}` |
| 删除 | `DELETE /api/accounts/{account_id}` |
| 测试 | `POST /api/accounts/{account_id}/test` |
| 切换状态 | `POST /api/accounts/{account_id}/toggle-status` |
| 调整优先级 | `POST /api/accounts/{account_id}/adjust-priority?delta=<整数>` |

说明：桌面端批量测试只是在统一弹窗中逐个调用单账号测试接口，不再提供单独的批量测试 API。
