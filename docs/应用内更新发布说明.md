# 应用内更新发布说明

AIMux 使用 Tauri 官方 updater 在 Windows 和 macOS 上下载、校验、安装并重启应用。客户端从 GitHub Release 的固定地址读取 `latest.json`，不会调用容易触发匿名限流的 GitHub REST API。

## 首次配置

项目的更新签名私钥保存在开发机的 `src-tauri/keys/updater.key`，该目录已被 Git 忽略。私钥必须备份到安全位置；丢失后，已安装的客户端将无法验证未来的新更新包。

在 GitHub 仓库的 `Settings -> Secrets and variables -> Actions` 中，新建 Repository secret：

| 名称 | 值 |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | `src-tauri/keys/updater.key` 的完整内容 |

当前项目密钥没有设置密码，因此 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 可以不创建；如果以后使用带密码的密钥，则必须同时创建这个 Secret。

不要提交私钥、不要把私钥放在 Release 附件、不要在 issue 或日志中输出私钥。

## 发布结果

推送 `v*` tag 后，GitHub Actions 会生成并发布：

- 常规安装包：Windows x64/arm64 的 `.exe`，macOS arm64 的 `.zip`。
- 更新包和签名：Windows x64/arm64 的安装程序 `.exe` 与 `.exe.sig`，macOS arm64 的 `.app.tar.gz` 与 `.sig`。
- `latest.json`：按运行平台和 CPU 架构指向对应更新包，包含 Tauri 签名。

macOS x64（Intel）不再提供新版本安装包或更新清单条目，已有用户可继续使用历史版本。

构建会在开始时检查 `TAURI_SIGNING_PRIVATE_KEY`。没有配置该 Secret 时，正式 tag 发布会失败，避免发布无法自动更新的版本。

## 用户行为

首次安装包含 updater 的版本仍需要通过 Release 页面手动安装。之后，用户点击侧栏“检查更新”即可在应用内完成下载、签名校验、安装和重启；下载或安装失败时可选择“手动下载”。

macOS 未做 Apple 代码签名和公证时，自动更新包仍可生成，但 Gatekeeper 的“应用已损坏”等系统提示不属于 updater 能够绕过的范围。
