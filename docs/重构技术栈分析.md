# AIMux Rust 技术栈说明

## 1. 当前结论

AIMux 已完成从旧桌面实现到 Rust/Tauri 2 的迁移，仓库根目录就是唯一开发和发布项目。旧实现不再参与启动、构建、测试或发布。

当前技术栈：

- Rust stable、Tokio、Axum、Reqwest、Tracing
- SQLx + SQLite
- Tauri 2
- Vue 3 + Vite + TypeScript
- Element Plus、Element Plus Icons、Pinia
- 少量自定义 SCSS/CSS

## 2. 选择理由

Rust 负责网关、调度、流式传输、监控后台和数据库访问，适合长期运行的本地服务和跨平台发布。Tauri 提供轻量桌面壳和系统能力，Vue/Element Plus 提供成熟的管理表格、分页、表单、弹窗和通知组件。

不再引入第二套完整前端样式体系，避免 Element Plus 和其他 CSS 框架互相覆盖。业务规则只在 Rust service 层实现一次，桌面页面和外部客户端都通过 HTTP API 访问。

```text
│  │  ├─ schema/       # API DTO
│  │  ├─ gateway/      # OpenAI/Anthropic 和 SSE
│  │  ├─ upstream/     # Reqwest、代理和超时
│  │  ├─ database/     # 连接池和健康检查
│  │  └─ background/   # Tokio 后台任务
│  └─ migrations/      # SQLx SQL migration
├─ src/
│  ├─ api/             # 前端 API 层
│  ├─ stores/          # Pinia 状态
│  ├─ pages/           # 页面
│  ├─ components/      # 可复用组件

```

## 4. 数据库兼容

Rust 直接使用当前用户数据目录下的 `aimux.db`，稳定端口 `7789`、开发端口 `7790` 共用同一文件。现有业务表、字段名和数据不变；`src-tauri/migrations/0001_baseline.sql` 是首个 Rust 基线，后续只追加 SQLx migration。

SQLx 使用 `_sqlx_migrations` 记录版本。历史 `alembic_version` 表如存在则保留，但 Rust 不读取、不更新、不删除。数据库结构变化必须遵守 [数据库迁移升级规划](docs/plan/数据库迁移升级规划.md)。

## 5. 请求和流式处理

调度按协议、模型、启用状态、优先级降序、倍率升序选择账号；模型映射在账号选中后解析。每次重试重新取号。非流式请求完成后解析 usage；流式请求先创建使用记录，收到结束事件或读取异常时更新最终状态，保证失败和 Token 数据不丢失。

请求体和提示词不做业务改写，OpenAI 与 Anthropic 保持协议隔离。上游代理和超时由设置统一注入 Reqwest client。

## 6. 开发和发布

- 前端：`npm run dev` 或 `scripts/windows/dev_start_frontend.bat`
- 桌面端：`npm run dev:desktop` 或 `scripts/windows/dev_start_desktop.bat`
- Rust 网关：`npm run dev:gateway` 或 `scripts/windows/dev_start_rust.bat`
- Windows 打包：`scripts/windows/stable_build_windows.bat`
- GitHub Actions：推送 `v*` tag 后构建 Windows x64/arm64 和 macOS arm64

日常改动只测试受影响路径；跨模块、数据库、网关生命周期和发布流程改动才运行完整检查。仓库默认不自动 commit 或 push。
