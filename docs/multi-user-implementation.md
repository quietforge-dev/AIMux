## 用户与认证

用户表 users 保存身份、Argon2 密码哈希、角色、启用状态和单个 API Token 的 SHA-256 哈希。数据库约束确保只有一个管理员，不能删除、降级或禁用该管理员。创建用户只允许普通角色；API 输入不能指定身份或提升权限。

API Token 用于 /v1 下的 OpenAI/Anthropic 兼容接口，不能操作 Web 管理 API。新用户创建及本人重置 Token 时仅返回一次明文，之后只展示前缀。旧 Token 重置后不再通过认证，已经开始的请求可能继续完成。

Web 登录返回独立的会话 Token，浏览器 localStorage 保存会话，数据库 web_sessions 只保存哈希。会话有效期 7 天，刷新页面及服务重启不会丢失。退出只撤销当前会话；修改/重置密码、禁用用户撤销该用户的全部会话。会话不能代替 API Token 访问 /v1。登录具有尝试次数和密码校验并发限制。

桌面端前端通过 Tauri 获取只在内存中保存的进程级凭据访问管理接口，不复用浏览器会话。桌面原 API Token 仍可调用本机接口；历史未配置 Token 的桌面网关保持原有兼容行为，Web 网关始终要求有效 Token。

## 配置归属

| 存放位置 | 内容 |
| --- | --- |
| 用户数据目录 aimux.db / users | 登录身份、密码哈希、每用户 API Token 哈希与前缀 |
| aimux.db / user_settings | 每用户代理、重试、超时、优先级策略、监控偏好等业务配置 |
| aimux.db / 业务表 | 非空 user_id 归属及关联校验；新写入不默认归入管理员 |
| settings.json / 环境变量 | 机器监听地址、端口、自启动；首次导入旧配置的来源 |
| 内存 | 每用户策略计数、任务句柄、桌面进程凭据 |

Web 设置页不能修改机器监听地址、端口或自启动。桌面保留这些控制，端口变更需要重启。桌面只在机器配置改变时重写 settings.json；业务偏好保存到数据库。机器配置写入失败会回滚本次数据库保存；数据库提交失败时尝试恢复原机器配置，并明确记录恢复失败。

每次启动不会重新覆盖用户设置。首次初始化会把原 settings.json 的业务偏好和旧 API Token 导入默认用户，导入和初始化标记在同一个事务提交。旧文件中的明文 Token 不再作为持续更新来源；后续可移除旧文件中的业务字段与 Token，仅保留机器配置。配置文件损坏会停止启动并报告错误，避免静默使用默认值导入错误配置。

## 升级步骤

1. 停止旧 AIMux 进程；保留原二进制及部署配置。
2. 备份用户数据目录的 aimux.db 和 settings.json。SQLite 使用 backup API 或 sqlite3 的 .backup 命令获得一致备份，避免只复制仍有 WAL 写入的主文件。
3. Web 首次升级在服务环境中设置 AIMUX_ADMIN_USERNAME 和 AIMUX_ADMIN_PASSWORD（密码 8 到 256 字节）。监听地址/端口仍可通过 AIMUX_HOST 和 AIMUX_PORT 设置。不要把真实密码放入仓库。
4. 启动新版。SQLx 自动执行追加迁移，将全部历史数据归属于内部 ID 为 local 的管理员；历史设置和 Token 只导入一次。桌面升级自动完成，无需设置管理员密码。
5. Web 使用初始化的管理员账号登录，在用户管理页创建同事账号；将创建时返回的个人 API Token 交给对应用户。新用户使用默认业务设置，不复制管理员的代理、账号或上游密钥。
6. 管理员后续在界面改密码不会被原环境变量覆盖。初始化成功后可移除初始化密码变量。桌面数据库首次用于 Web 时需要同样设置 Web 初始化凭据，但不会重新导入覆盖已保存的设置。
7. 验证原有账号、模型、统计与监控数据仍在；用第二个用户验证自己的空业务空间及 /v1 转发。下游调用各自的 API Token。

本次迁移重建业务表，不能让旧版和新版同时使用升级后的数据库。需要回退时停止新版，恢复升级前的完整数据库备份、settings.json 与原二进制。回退会丢弃升级后产生的数据，应先单独保留新版数据库副本。

## 验证与实现边界

自动测试覆盖从有历史数据的旧结构升级、用户之间的读写/关联/统计/清理隔离、持久化会话和过期、权限拒绝、Token 重置、初始化幂等、错误设置事务回滚、桌面身份，以及普通/流式网关请求归属。浏览器使用独立内存库验证管理员创建用户、一次性 Token 展示、普通用户路由限制及刷新保持登录。测试不访问本机真实或线上数据库。

业务隔离由服务身份、绑定 user_id 的 SQL 和关联约束共同实现。SQLite 文件仍由同一个服务进程持有，拥有服务器或数据库文件管理权限的人可以访问全部数据。禁用用户阻止后续请求并停止任务，已开始的前台请求可能继续完成，不会转移到其他用户。多用户共享一台服务器的 CPU、内存和网络；当前没有按用户限制配额或并发。
